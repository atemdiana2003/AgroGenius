# Decisions and assumptions

1. **Source documents:** `AgroGenius_HarvestGuard_System_Architecture.pdf` and `Document1.pdf` were reviewed locally from the project owner's external documents folder. They remain outside this repository; the traceability matrix records their requirements and page references without adding them as project assets.
2. **Monorepo:** One Express/Prisma API, one shared-contract workspace, and an empty frontend handoff rather than a built React application.
3. **Versioning:** `/api` is the prototype base. Future breaking changes should add `/api/v1`; do not silently change field meanings.
4. **Auth:** Browser refresh uses an HttpOnly SameSite=Lax cookie; non-browser clients may receive a refresh-token body field. Production requires `COOKIE_SECURE=true`, HTTPS, and reviewed cookie/CSRF deployment settings.
5. **Registration:** Self-registration accepts only FARMER or BUYER; admin provisioning is operator-controlled. Phone/email uniqueness uses normalized values.
6. **Experimental inputs:** Defaults are broad plausible-input bounds (-10 to 60 °C) and illustrative configurable project alert ranges. Neither setting is a food-safety guarantee. Teams must select and label protocol thresholds with their supervisor.
7. **Market prices:** All entered prices are historical, sourced observations, never verified live/official feeds. `XAF` is an accepted currency, not a forced currency. Demo market has an unmistakable DEMO label.
8. **Units:** KG, CRATE, and PIECE are separate dimensions with no implicit conversion. Trials should use comparable KG mass.
9. **Offline scope:** Server idempotency/version-conflict support is implemented; browser IndexedDB and PWA behavior belongs to the future client and is manual verification.
10. **SMS:** No real provider is configured. The development adapter records `SIMULATED`; `disabled` records failure. Cameroon carrier coverage, sender rules, local consent and costs must be confirmed before a real adapter is added.
11. **ESP32:** Firmware is a starter, not field- or hardware-verified. TLS uses a configured trusted root CA and fails closed without it; RAM offline queue does not survive reset/power loss. Device keys are provisioned by an administrator and must be stored outside version control.
12. **Administration:** No default admin account/password is seeded. Provision an administrator through a restricted, audited operator process.
13. **Transaction retries:** Serializable conflicts produce a safe 409 and caller can retry with same idempotency key. API does not silently replay arbitrary business conflicts.
14. **Pilot metrics:** Counts report stored records, not outcomes. Loss reduction/profit are deliberately not inferred from observations.
15. **Maturity:** Initial SQL migration was generated from Prisma and augmented with PostgreSQL integrity checks. These checks are database-only additions and should be preserved in future schema migrations.
16. **Database verification:** Migrations, seed and PostgreSQL integration tests must use a newly created disposable database ending in `_test`; do not use any workstation, shared or production database. A fresh PostgreSQL 17 disposable cluster was used for the recorded tests.
17. **Optional offer payment:** The source documents do not define a payment obligation, platform fee, escrow or payout. The only implemented collection purpose is optional buyer payment for an already seller-confirmed accepted offer. `BuyerOffer.offeredPrice` is treated as the agreed total (not a per-unit price), and payment is available only when that amount is an integer XAF value of at least 100. The amount is never inferred from listing prices, quantities or a fee schedule. Payment initiation/status does not reserve, sell, decrement or transfer inventory; the existing seller-confirmation workflow remains authoritative. No payment is created for browsing, harvest, readings or price observations.
18. **Fapshi safety:** Fapshi credentials are service-specific secrets injected via a local ignored `.env` or deployment secret manager. The provider adapter uses fixed documented sandbox/live hosts and never retries a collection request automatically. If an initiation times out before a transaction ID is saved, the intent remains `INITIATION_UNKNOWN` and requires support reconciliation; do not retry it with a new idempotency key until reconciled.
