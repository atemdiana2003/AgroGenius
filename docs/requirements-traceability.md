## Validation record

- Fapshi changes are covered by adapter unit tests and PostgreSQL payment-workflow integration tests; no Fapshi credentials/account, public callback, sandbox transaction, or live transaction were available or used. Payments remain disabled by default and production use requires confirmation of the documented business assumption.
- Fresh disposable PostgreSQL validation for the payment-hardening pass: all three migrations deployed, seed completed, and 24 tests passed across 6 files. A separate API smoke run returned HTTP 200 for `/health` and `/ready`.
- Final non-database validation: 20 passed, 4 DB-only skipped; typecheck and production build passed. Full lint passed; formatting and OpenAPI contract checks passed after the traceability update; dependency audits reported zero vulnerabilities.
- A clean isolated `npm ci --ignore-scripts` probe using root/workspace manifests and lockfile passed. `npm ci` in the live working tree was attempted but Windows returned `EBUSY` while removing a package directory locked by another process; no destructive cleanup of the shared Node process was attempted.
- Node `v24.1.0`, npm `11.6.2`. Docker and PlatformIO are not installed; Git Bash and PostgreSQL 17 utilities are available, but no physical ESP32/sensor is available.
- PostgreSQL-backed checks and restore drills must use newly created disposable databases with a name ending in `_test` or `_restore_test`; never use a production or existing user database.
- GitHub Actions, Docker image build, firmware compilation/hardware calibration, external provider delivery, production deployment and frontend/PWA behavior are not claimed as tested. The PostgreSQL adapter emitted a non-fatal `pg` concurrent-query deprecation warning during the concurrent-workflow test.
